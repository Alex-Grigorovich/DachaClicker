# Clicker Design Doc (актуально)

## 1) Краткий статус проекта

Проект — рабочий прототип кликера на Cocos Creator с базовой экономикой, квестами, разблокировками, сохранением прогресса и адаптацией UI под разные разрешения.

Базовый цикл:

1. Игрок кликает по культуре.
2. `VegClickMoney` начисляет валюту через `MoneyManager`.
3. `QuestManager` обновляет прогресс заданий.
4. Через `SlotMenuHandler` открывается `VegetableMenuHandler`.
5. Игрок сажает/разблокирует культуру.
6. `PlantFieldState` фиксирует посадку.
7. `ProgressManager` сохраняет изменения.

## 2) Что реализовано

### Экономика и клик

- `MoneyManager` — единый источник правды для баланса и `totalEarned`; индикатор пассивной скорости `MoneyDPS` (`+X/с`, `formatPassiveIncomePerSecond`, опционально `@property passiveIncomeLabel` или поиск соседа `MoneyDPS` у родителя `moneyLabel`).
- `VegClickMoney`:
  - клик с защитой от `TOUCH_END + MOUSE_UP`;
  - локальный кулдаун;
  - анимация культуры и полет монеты в `Moneybar`;
  - обновление квестового прогресса через `QuestBridge`.

### Поле и посадки

- `SlotMenuHandler` открывает `VegetableList` по клику на слоты поля (в т.ч. занятые), обновляя `targetCell`.
- `PlantFieldState` хранит `cell -> culture`.
- Восстановление посадок: приоритет `slotId`, затем fallback по `uuid` и `name` (важно для Preview).

### Культуры и разблокировки

- Баланс культур читается из `assets/resources/balance/BALANCE_DATA.json`.
- Разблокировки культур вынесены в `UnlockManager`:
  - `VegetableMenuHandler` только отображает состояние и вызывает `unlockCulture`;
  - `QuestManager` метрику `unlocked_cultures_count` берет из этого же слоя;
  - `ProgressManager` сохраняет/восстанавливает `unlockedCultures`.
- Замки слотов остаются в `CellLockHandler` и квестовых наградах `unlock_slot`.

### Отказ при нехватке денег и клик по замку (UX)

- Общая утилита: `UiMoneyDenyFeedback.ts` — горизонтальная тряска (`shakeNodeHorizontal`), краткая красная подсветка `Sprite`/`Label` в поддереве (`flashSubtreeRed`), комбо `shakeAndFlashRed`, поиск нод по имени и подсветка списка имён (`flashNamedNodesRed`).
- **Меню культур** (`VegetableMenuHandler`): при попытке купить разблокировку без достаточной суммы или при неуспешном `subtractMoney` — **тряска + красная вспышка** на ноде блока (`cellListBlockCabbage`, `cellListBlockTomato`, `cellListBlockChiliPepper` и т.д. по балансу). Клик по строке завязан на hit-ноду (в т.ч. `cellList`), чтобы событие не терялось на дочерних спрайтах.
- **Замки ячеек** (`CellLockHandler`): при клике по активному замку — **тряска корня `lockNode`** и **красная вспышка** нод `Lock1` / `Lock2` / `Lock3` (если есть в иерархии; иначе — fallback на всё поддерево `lockNode`). События `TOUCH_END` / `MOUSE_UP` вешаются на `lockNode` и все потомки с `UITransform` (клик по дочерним спрайтам/лейблу). У квестовых замков с `lockWithoutPrice` — только визуальный отклик, покупка за деньги не выполняется.

### Квесты

- `QuestManager` загружает квесты из `BALANCE_DATA.json`.
- Поддержаны метрики:
  - `total_clicks`, `total_earned`, `current_money`,
  - `planted_slots_count`, `unlocked_cultures_count`,
  - `passive_earned` (накоплено с пассивного тика и оффлайн-пассивки),
  - `opened_slot_4`, `opened_slot_5`, `opened_slot_6`.
- Награды: `money`, `unlock_slot`.

### Сохранение прогресса

- `ProgressManager` — singleton-оркестратор сохранения/восстановления.
- Хранилище: `sys.localStorage`, ключ `farm_clicker_progress_v1`.
- Формат сейва: `PROGRESS_SAVE_VERSION = 4`.
- Сохраняются:
  - деньги (`balance`, `totalEarned`);
  - квесты (`activeIndex`, `totalClicks`, `passiveEarned`);
  - посадки (`fieldCells`);
  - разблокированные культуры (`unlockedCultures`);
  - замки (`cellLocks`);
  - уровни апгрейдов (`upgrades`).
  - пассивный доход (`passiveIncome`: `lastSessionTimestamp`, `autoCollectEnabled`, `autoCollectEfficiency`).
- Миграции:
  - есть цепочка `MIGRATIONS`;
  - реализованы шаги `v1 -> v2` (поле `upgrades`), `v2 -> v3` (`fieldCells[].slotId`, `cellLocks[].slotId`) и `v3 -> v4` (поля `passiveIncome`, `quests.passiveEarned`).
- Для тестов:
  - `ProgressManager.disableSaving`;
  - `ResolutionAdapter.disableProgressSaving`;
  - при отключении сохранения UI не читает `localStorage` (`ProgressBridge.isProgressPersistenceDisabled`).

### Апгрейды

- Данные апгрейдов уже есть в `BALANCE_DATA.json`.
- `UpgradeProgressStore` хранит уровни и интегрирован в сейв.
- `UpgradeManager` внедрён как доменный слой:
  - загрузка и валидация апгрейдов из баланса;
  - покупка уровней через `purchase(id)` с проверкой unlock/cost/maxLevel;
  - применение эффектов к клику (`add_click_income_flat`, `add_crop_click_income_flat`, `global_click_bonus_percent`, `double_click_chance_percent`);
  - модификация кулдауна (`cooldown_multiplier`, `extra_cooldown_multiplier`);
  - бонус к денежным наградам квестов (`quest_money_bonus_percent`);
  - скидка на открытие культур (`culture_unlock_discount_percent`);
  - пассивный доход и автосбор (`passive_income_bonus_percent`, `auto_collect_unlock`, `auto_collect_efficiency_percent`).
- `UpgradeListPanel` довязан к `UpgradeManager`:
  - строки `ColList` сопоставляются с `upgradeId` через встроенный mapping + `rowBindings`;
  - покупка по клику с защитой от дублей и единым deny-feedback (`shakeAndFlashRed`);
  - обновление уровней/цен в строках (`LevelText`, `CostText`) и внешних cost-лейблах;
  - после покупки принудительно обновляются активные `VegClickMoney` для корректных UI-значений.
- `UpgradeListToggle` управляет открытием/закрытием панели с анимацией и интеграцией в `ResolutionAdapter.fitUpgradeList`.

### Пассивный доход/автосбор

- Введён `PassiveIncomeManager`:
  - загрузка `passiveIncomePerSecond` по культурам из `BALANCE_DATA.json`;
  - тиковое начисление (агрегация дробной части, выдача целыми через `MoneyManager.addMoney`);
  - применение модификаторов из `UpgradeManager` (`passive_income_bonus_percent`, `auto_collect_unlock`, `auto_collect_efficiency_percent`).
- `QuestBridge` расширен уведомлением пассивного заработка; в `QuestManager` добавлена метрика `passive_earned`.
- `QuestManager` инициирует и тикает пассивку (`PassiveIncomeManager.initialize(...)` + `step(dt)`).
- В `BALANCE_DATA.json`:
  - добавлен `passiveIncomePerSecond` для базовых культур;
  - `tracking_keys` расширен ключом `passive_earned`;
  - добавлены апгрейды `autocollect`, `passive_income`, `auto_collect_efficiency`.
- В `UpgradeList` добавлены строки и `rowBindings` для новых апгрейдов:
  - `AutoCollect -> autocollect`;
  - `PassiveIncome -> passive_income`;
  - `AutoCollectEfficiency -> auto_collect_efficiency`.
- Индикатор `MoneyDPS`: обновляется из `MoneyManager` (`formatPassiveIncomePerSecond`, текущая скорость из `PassiveIncomeManager.getCurrentIncomePerSecond()`).
- Оффлайн-пассивка: после восстановления сейва `ProgressManager` вызывает `PassiveIncomeManager.applyOfflineCatchUp(lastSessionTimestamp)` (кэп `offlineCapSeconds` в балансе).
- Квесты с `passive_earned`: `quest_passive_first_gold`, `quest_passive_steady`, `quest_passive_big` (первый также в `minimal_first_implementation`).
- Техническая деталь: чтобы избежать циклического импорта `MoneyManager` ↔ `PassiveIncomeManager`, начисление денег из `PassiveIncomeManager` идёт через ленивый `require('./MoneyManager')`.

### UI/сервис

- `ResolutionAdapter` масштабирует `GameField`, боковые панели, `VegetableList`, `VegetableListUnlocked`, `UpgradeList`.
- `ExclusiveUIPanels` обеспечивает взаимоисключение основных окон (`VegetableList`, `VegetableListUnlocked`, `UpgradeList`, `Tasks`): при открытии одного остальные закрываются автоматически.
- `FontLoader` переведен на мягкую загрузку:
  - путь `fontResourcePath` (по умолчанию `resources/fonts/Caveat`);
  - при ошибке — `console.warn` (без жесткого `console.error`).

## 3) Текущие ограничения и договоренности

### Preview-шум

- `You are trying to destroy a object twice or more` — существенно снижен:
  - защита по `isValid` в `VegClickMoney`;
  - отказ от автоматического `addComponent('ProgressManager')` в `AdaptiveScale`.
- `IPC message has been lost` — ограничение Preview/Electron; на билд напрямую не переносится.

### Идентификаторы ячеек

- Введен стабильный `slotId` в сейве (`fieldCells`, `cellLocks`) и в runtime-сопоставлении.
- Для совместимости со старыми/нестабильными данными в Preview сохранены fallback'и по `uuid` и `name`.

### Поиск по строковым именам

- Для scene/UI стоит продолжать выносить ссылки в `@property`.
- Исключение: логика, завязанная на контракт префаба культуры (`VegClickMoney`, поиск `VegClick`, `IconCoin` и т.п.), может оставаться на стабильных именах внутри префаба.

### Moneybar и `MoneyDPS`

- На ноде **`MoneyDPS`** должен быть только **`Label`** (и при необходимости `UITransform`). **Не вешать второй `MoneyManager`** на `MoneyDPS`: singleton уничтожит дубликат вместе с нодой и сломает индикатор.
- Основной **`MoneyManager`** остаётся на ноде с основным балансом (например контейнер с `MoneyTextCount`).

## 4) Приоритеты на следующий этап

### Высокий

1. **Сделано:** апгрейды доведены до игрового UI:
   - покупка и валидация через `UpgradeManager`;
   - UI-интеграция через `UpgradeListPanel`/`UpgradeListToggle`;
   - эффекты уже работают в клике/кулдауне/квест-наградах/скидке на unlock;
   - уровни апгрейдов сохраняются и восстанавливаются через текущий save-flow.
2. **Сделано:** стабильные `slotId` и цепочка миграций сейва до актуального формата **v4**:
   - `ProgressSave`: шаг `v2 -> v3` для `fieldCells[].slotId` и `cellLocks[].slotId`; шаг `v3 -> v4` для `passiveIncome` и `quests.passiveEarned`;
   - `ProgressManager`/`VegetableMenuHandler`: сохранение и восстановление в первую очередь по `slotId` (с fallback на `uuid`/`name`).
3. **Следующий шаг:** закрыть UX-ветку денежных отказов:
   - добавить опциональный аудио-фидбек к `UiMoneyDenyFeedback`;
   - при необходимости вынести настройки deny-feedback в editor-friendly компонент.
4. **Сделано:** внедрён MVP пассивного дохода/автосбора:
   - доменный слой `PassiveIncomeManager` с тиковым начислением;
   - интеграция в квесты через `passive_earned`;
   - расширение сейва до `v4` и миграция `v3 -> v4`;
   - добавлены профильные апгрейды и UI-строки в `UpgradeList`.
5. **Сделано:** итерация 2 пассивки — индикатор `MoneyDPS`, квесты на `passive_earned`, оффлайн-пассивка после загрузки (`applyOfflineCatchUp`, кэп `offlineCapSeconds` в `BALANCE_DATA.json`).

### Средний

1. **Сделано:** уменьшен string-based поиск по сцене:
   - `VegClickMoney` уже использует явные ссылки `canvasRoot` и `moneybarRoot`;
   - в `VegetableMenuHandler` добавлены `@property` для критичных узлов (`rowsRoot`, `cultureRows`, `cultureBlocks`, `unlockMenuNode`) с fallback на поиск по имени;
   - в `UpgradeListToggle` добавлены `@property` (`searchRoot`, `adaptiveScale`) с fallback на поиск по сцене;
   - изменения сделаны без правки префабов (runtime-only).
2. **Сделано:** подготовлена стратегия миграций сейва (актуальный формат **v4**, цепочка `MIGRATIONS`):
   - в `ProgressSave.ts` добавлен `PROGRESS_SAVE_MIGRATION_PLAN`;
   - добавлена runtime-проверка полноты цепочки `MIGRATIONS` с предупреждением в лог, если шагов не хватает.
3. **Сделано:** формализован smoke/regression-проход (минимальный чеклист):
   - **Шаг 1 (чистый старт):** удалить localStorage-ключ `farm_clicker_progress_v1`, запустить сцену; ожидаемо: баланс 0, только базовая культура, стартовые слоты/замки в дефолте.
   - **Шаг 2 (базовый прогресс):** заработать деньги, посадить культуры в несколько слотов, открыть 1-2 культуры через `VegetableListUnlocked`; ожидаемо: UI и квест-метрики обновляются без ошибок.
   - **Шаг 3 (апгрейды):** купить несколько апгрейдов в `UpgradeList`; ожидаемо: уровни/цены обновились, эффекты применяются к клику/кулдауну/стоимости unlock.
   - **Шаг 4 (перезагрузка):** reload сцены/перезапуск Preview; ожидаемо: корректно восстановлены `money`, `upgrades`, `unlockedCultures`, `fieldCells`, `cellLocks`.
   - **Шаг 5 (v2->v3 совместимость):** загрузить старый сейв без `slotId`; ожидаемо: миграция в `v3` проходит автоматически, посадки и замки матчатся по `slotId`/fallback без потерь.
   - **Шаг 6 (пассивка / DPS / оффлайн):** купить `autocollect`, посадить культуры; ожидаемо: на `MoneyDPS` отображается `+X/с`, баланс растёт без клика, `passive_earned` и квесты на него прогрессируют. Закрыть игру на ≥2 мин (или подставить старый `lastSessionTimestamp` в сейве), снова открыть; ожидаемо: разовое начисление оффлайн-пассивки (не выше кэпа `offlineCapSeconds`), затем в сейве обновляется `passiveIncome.lastSessionTimestamp`.
4. При необходимости расширить `UnlockManager` на другие типы разблокировок.

### Низкий

1. **Пассивный доход/автосбор**
   - **Сделано (MVP):**
     - базовая пассивка по культурам (`passiveIncomePerSecond`) с тиковым начислением;
     - `PassiveIncomeManager` и интеграция с `UpgradeManager`/`QuestManager`;
     - квестовая метрика `passive_earned` и сохранение состояния автосбора в `ProgressSave v4`;
     - UI-строки апгрейдов под пассивку/автосбор в `UpgradeList`.
   - **Сделано (итерация 2):**
     - индикатор пассивного дохода `+X/с` на ноде `MoneyDPS` (привязка из `MoneyManager`, формат `formatPassiveIncomePerSecond`);
     - квесты линейки с метрикой `passive_earned`: `quest_passive_first_gold`, `quest_passive_steady`, `quest_passive_big`;
     - оффлайн-пассивка после загрузки сейва: `PassiveIncomeManager.applyOfflineCatchUp` + кэп `offlineCapSeconds` в `BALANCE_DATA.json`, время отсчёта от `passiveIncome.lastSessionTimestamp` (обновляется при сохранении).
   - **Осталось (полировка):**
     - добавить мягкий VFX/аудио фидбек тика дохода (без визуального спама).

2. **Комбо/синергии культур**
   - **Цель:** повысить глубину выбора посадок (не только "самая дорогая культура").
   - **MVP-механика:**
     - ввести набор синергий как правила "условие -> бонус":
       - по соседству (`adjacency_bonus`);
       - по наборам (`set_bonus`, например 2 томата + 1 перец);
       - по разнообразию (`diversity_bonus`, бонус за N разных культур).
     - применять бонус к клику, пассивному доходу или обоим каналам отдельно.
   - **Архитектура:**
     - добавить `SynergyManager`:
       - подписка на изменения `PlantFieldState`;
       - пересчет активных синергий в батче;
       - выдача итоговых множителей в `UpgradeManager`/`PassiveIncomeManager`.
     - важно: итог формировать через единый pipeline модификаторов, чтобы не дублировать формулы в разных местах.
   - **Данные:**
     - в `BALANCE_DATA.json` добавить секцию `synergies`:
       - `id`, `type`, `conditions`, `effects`, `priority`, `stackingRule`;
       - явные правила стакания (`additive`, `multiplicative`, `max_only`).
   - **UI/UX:**
     - подсветка активных синергий в `VegetableList`/отдельной панели;
     - короткий tooltip "Активно: +15% к пассивному доходу";
     - при перестановке/посадке мгновенный пересчет и визуальный отклик.
   - **Тестовый минимум:**
     - юнит-тесты на расчет синергий (граничные случаи и стакание);
     - regression-check: одинаковый результат при одинаковой конфигурации слотов после save/load.

3. **Расширение контента (новые культуры, слоты, VFX)**
   - **Цель:** ускорить выпуск нового контента без правок core-кода.
   - **Культуры:**
     - стандартизировать content-pipeline "добавил запись в баланс -> появился в UI":
       - обязательные поля: цена unlock, доход клика, пассивный доход, иконка/префабные ссылки;
       - валидация `BALANCE_DATA.json` при загрузке (ошибки/предупреждения).
     - поддержать tier-модель (ранние/средние/поздние культуры) для предсказуемой прогрессии.
   - **Слоты:**
     - расширить `cellLocks` как data-driven:
       - стоимость, тип unlock (деньги/квест/ивент), визуальный стиль замка;
       - совместимость с текущим `slotId`-подходом.
     - подготовить задел под "особые слоты" (буст-зоны, редкие бонусы) через `slotTags`.
   - **VFX:**
     - ввести `VfxCatalog` (или аналогичный конфиг) с ключами эффектов:
       - `click_hit`, `money_tick`, `unlock_success`, `combo_activate`;
       - quality-профили (`low/medium/high`) и fallback на low.
     - ограничить частоту спавна эффектов (rate-limit), чтобы избежать просадки FPS.
   - **Производственный процесс:**
     - чеклист на каждый контент-пак:
       - запись в баланс;
       - локализация названия/описания;
       - проверка UI в `ResolutionAdapter`;
       - smoke на save/load и квестовые метрики.
   - **Критерии готовности:**
     - добавление новой культуры/слота выполняется без изменения TypeScript-логики;
     - эффекты не создают заметных просадок на целевых устройствах;
     - контент корректно переживает миграции сейва.

## 5) Целевая архитектура (коротко)

### Ядро

- `MoneyManager` — деньги и `totalEarned`.
- `ProgressManager` — save/load и жизненный цикл восстановления.
- `UnlockManager` — доменный статус разблокировок культур (дальше расширяем).
- `PlantFieldState` — состояние посадок.
- `UpgradeManager` — уровни апгрейдов и применение эффектов; UI-покупки и отображение статусов обслуживаются через `UpgradeListPanel`.
- `PassiveIncomeManager` — тиковый пассивный доход/автосбор на основе посадок и апгрейдов.

### Игровые компоненты

- `VegClickMoney`, `SlotMenuHandler`, `VegetableMenuHandler`, `CellLockHandler`, `QuestManager`.
- `UiMoneyDenyFeedback` — чистые функции тряски/красной вспышки для отказов по деньгам и замкам (без компонента на сцене).

### Данные

- `BALANCE_DATA.json` — культуры (включая `passiveIncomePerSecond`), квесты, слот-прогрессия, апгрейды, глобальный кэп оффлайна `offlineCapSeconds`.
- `ProgressSave.ts` — версия формата, миграции и типы сейва.

## 6) Итог

Фундамент прототипа стабилен: деньги, посадки, квесты, разблокировки, апгрейды и базовый пассивный доход/автосбор переживают перезапуск сцены через persist-сейв.

Критичный шаг со стабильными `slotId` уже закрыт (миграция `v2 -> v3` в проде), а ветка пассивки включает MVP + индикатор `MoneyDPS`, квесты на `passive_earned` и оффлайн-пассивку с кэпом. Дальше — UX-полировка денежных отказов (звук/настройки из редактора) и опциональный VFX тика пассивки.

## 7) Перспектива развития: что добавить и чего избегать

Раздел задаёт общий вектор, не привязанный к ближайшим спринтам. Используется как фильтр идей: «хороший кандидат / антипаттерн для жанра / преждевременная сложность».

### 7.1 Что стоит добавить (по убыванию ценности)

#### Игровые системы

- **Престиж / soft reset.** Классический long-term loop кликера: сброс прогресса в обмен на «престижные очки», дающие перманентный множитель. Подключать, когда контент исчерпывается за 1-2 часа активной игры.
- **Оффлайн-доход (расширение).** Базовая оффлайн-пассивка уже есть (`applyOfflineCatchUp` + `offlineCapSeconds`). Дальше — UX (экран «вы отсутствовали N времени»), отдельные множители, интеграция с рекламой «удвоить оффлайн».
- **Ежедневные награды / login bonus.** Дешёвая в реализации механика возврата.
- **Временные бусты.** «x2 на 2 минуты», расходники из квестов/магазина. Хорошо ложатся на синергии и пассивку.
- **Коллекция/альбом культур.** Мета-цель сверх прогрессии: бонусы за полный набор/тир.
- **Ачивки.** Статичные цели «на всё время», параллельно квестам, без давления.

#### Прогрессия и контент

- **Биомы / локации.** Новые поля со своим балансом и культурами — альтернатива «бесконечному списку культур» в одном поле.
- **События/сезоны.** Временные культуры и квесты с уникальными наградами; самый дешёвый способ освежить мету.
- **Косметика поля.** Скины, фоны, рамки слотов — без влияния на баланс.

#### Технические улучшения

- **Cloud save.** Перенос прогресса между устройствами через простой backend/внешний сервис; ключевое для мобильного релиза.
- **Аналитика событий.** Клики/покупки/уход — без неё дальнейшая балансировка идёт вслепую.
- **Локализация.** Вынести строки в `i18n`-словари; чем позже — тем дороже.
- **Аудио-подсистема.** `AudioManager` поверх Cocos Audio: пулинг, громкость по категориям (SFX/UI/music), глобальный mute. Подключается к существующему `UiMoneyDenyFeedback` (см. `Высокий` приоритет).
- **Юнит-тесты на доменные слои.** `MoneyManager`, `UpgradeManager`, `PassiveIncomeManager` (расчёт ставки/оффлайна), далее `SynergyManager` — чистые расчёты, легко покрываются.
- **CI-проверка баланса.** Автоматическая валидация `BALANCE_DATA.json` (схема, обязательные поля, ссылки на существующие культуры/апгрейды/слоты).

#### Монетизация (если планируется)

- **Реклама с наградой.** «x2 за просмотр», «удвоить оффлайн-доход» — естественно ложится на бусты.
- **Стартер-паки.** Одноразовые наборы для нового игрока.
- **Премиум-валюта.** Только если есть time-gates/бусты, иначе ломает баланс кликера.

### 7.2 Что НЕ стоит добавлять (или отложить надолго)

#### Технически избыточно для жанра

- **PvP / realtime-онлайн.** Кликер без сетевого ядра — другой проект; стоимость огромная, выгода сомнительная.
- **3D / сложные шейдеры.** Проект 2D-кликер, усложнение пайплайна не окупается.
- **Полноценная физика.** Для «клик + слот» не нужна; визуальные «отскоки» решаются tween'ами.
- **ECS / полная переархитектура.** Текущая компонентно-доменная схема справляется. Оправдано только при кратном росте числа сущностей на сцене.

#### Геймдизайн — антипаттерны для idle/clicker

- **Жёсткие штрафы за бездействие** (гниение посадок, штрафы за оффлайн): фрустрируют казуального игрока и ломают idle-петлю.
- **Pay-to-win в чистом виде.** Убивает прогрессию и retention.
- **Сложные мини-игры на каждый клик.** Размывает «дзен» кликера.
- **Принудительные таймеры >1 минуты на ранней игре.** Игрок уходит до первой петли удовольствия.
- **Случайность в core-прогрессии без pity-системы.** «Не выпала культура — играй ещё час» — токсично для жанра.

#### Анти-паттерны кода (договорённость команды)

- **Глобальный singleton-«BigManager».** Всё-в-одном плодит циклические зависимости. Поддерживаем доменные слои с явным API (`MoneyManager`, `UpgradeManager`, `UnlockManager`, дальше `PassiveIncomeManager`/`SynergyManager`).
- **Бизнес-логика в UI-компонентах.** Покупки/расчёты живут в `*Manager`; UI — только отображение и ввод.
- **Поиск нод по строковым именам в core-логике.** Допустимо только в зафиксированных местах (контракт префаба культуры). В новых местах — `@property` + fallback.
- **Прямое чтение/запись `localStorage` мимо `ProgressManager`.** Ломает инварианты сейва и миграции.
- **Хардкод чисел баланса в коде.** Все игровые параметры — через `BALANCE_DATA.json`.

### 7.3 Приоритизация перспективных задач

1. Закрыть оставшуюся часть «Низкого» roadmap: синергии → контент-пайплайн (блок пассивки по основному функционалу закрыт).
2. Добавить аудио + локализацию (низкая стоимость, высокий пользовательский эффект).
3. Подключить аналитику и cloud save — основа для тюнинга и удержания.
4. Внедрить престиж и расширение оффлайна (UI/мета/монетизация) — после стабилизации контента.
5. Монетизация и сезонные события — последним этапом, когда метрики уже видны.
